# 存储层说明与后端迁移指南

## 当前实现

首页方向合集：漫画方向与真实产品分层。`settings.homeContent.cards[].productIds` 可选；缺省按方向分类 / 阶段自动收录，数组是手动收录的产品 ID 集合（有序），空数组表示空合集。后台、首页产品数量与 `/directions/:id` 共用解析逻辑，只公开已发布且已上线的真实产品。无需清空 IndexedDB 或 PostgreSQL；旧配置缺少该字段时保持自动收录。方向编辑统一在「首页管理」，产品基础信息在「产品管理」。

2026-10-02 已实现服务端适配器 `http.ts`，默认通过同源 `/api` 访问 PostgreSQL；个人资料、收藏与访问历史仍保留 IndexedDB。只有明确设置 `VITE_STORAGE_MODE=local` 时才使用旧的纯浏览器模式。入口为 `src/storage/index.ts`，页面仍通过 `Repository` 异步接口读写。

服务端模式不会运行浏览器种子初始化或定时发布；初始化、权限校验、审计和定时发布均由后端负责。管理员 Cookie 是 HttpOnly，不把登录令牌写入本地存储。旧 IndexedDB 原样保留，可导出后由超级管理员确认合并迁移。完整行为与备份边界见 `server/README.md`。以下为保留的本地模式结构及历史迁移设计，不代表线上权限或存储实现。

- 接口：`repository.ts`。
- 浏览器适配器：`indexed-db.ts`。
- 当前数据库：`next-career-v1`，数据库版本：1。
- 初始化数据：`src/domain/seed.ts`；站点配置不存在时初始化完整种子数据。已有站点仅执行带迁移标记的增量补充，不重新写入用户产品与设置。
- 页面状态和操作：`src/app/context.tsx`。
- 数据模型及产品校验：`src/domain/models.ts`。

数据库由网站的来源隔离。例如 `http://127.0.0.1:5173` 与 `http://localhost:5173` 是不同来源。更换域名、端口、浏览器或设备不会自动共享数据。隐私模式、存储配额、清理站点数据均可能影响持久化，请定期备份。

## 接口契约

所有方法返回 Promise，调用者必须处理失败，不得在保存前显示成功。

```ts
interface Repository {
  list<K extends StoreName>(store: K): Promise<EntityMap[K][]>;
  get<K extends StoreName>(
    store: K,
    id: string,
  ): Promise<EntityMap[K] | undefined>;
  put<K extends StoreName>(store: K, value: EntityMap[K]): Promise<void>;
  remove(store: StoreName, id: string): Promise<void>;
  batch(operations: Operation[]): Promise<void>;
  exportData(): Promise<Backup>;
  importData(data: unknown): Promise<void>;
  clearPersonalData(): Promise<void>;
}
```

`put`、`remove` 等待事务真正提交。`batch` 在同一事务内写入多个表。导入先验证数据，再通过跨表事务整体替换；无效备份不能部分写入。生产后端不要直接公开一个能操作任意表的通用写接口，必须映射为按业务权限校验的端点。

## 当前边界

1. **本地入口锁不是服务端鉴权。** 口令通过 PBKDF2 加盐摘要保存，但拥有浏览器开发者工具的人可以修改本地数据和页面状态。它只减少本设备的误操作，不承担安全边界。
2. **统计仅描述本浏览器。** 页面访问和产品曝光不能代表全站 DAU/MAU。外链点击不代表目标产品加载成功、注册成功或完成核心动作。
3. **不能从浏览器确认任意外站可用性。** CORS 和网络环境会影响检测；页面只做 URL 协议、凭据和精确域名校验。DNS/TLS/重定向链必须由后端检查。
4. **不保存真正的支付密钥或签名密钥。** IndexedDB、前端环境变量和源代码都不是秘密存储位置。
5. **未启用统一登录或跨域身份。** 当前个人资料固定为本地资料，不伪装线上用户注册。
6. **页面关闭后没有可靠定时任务。** 定时发布需要打开页面或后续服务端任务执行。
7. **客户端数据不能直接支持 SEO。** 当前公开页面由 React 渲染；后端接入时为产品、分类、合集增加服务端渲染或静态生成，创建 Sitemap 和结构化数据。

## 替换后端的具体步骤

### 1. 确定服务边界

保留页面和领域模型，新增 `HttpRepository` 实现；产品、审核、用户和分析采用不同的后端服务端点。前端仍调用同一数据接口，不把网络请求散落到页面。

推荐映射：

| 本地能力     | 后端端点示例                                  | 关键约束                              |
| ------------ | --------------------------------------------- | ------------------------------------- |
| 产品目录     | GET /api/products                             | 仅公开已发布内容，支持分页与筛选      |
| 产品编辑     | PUT /api/admin/products/:id                   | 服务端鉴权、Schema 校验、乐观锁、审计 |
| 合集与推荐位 | /api/admin/collections、/api/admin/placements | 内容版本与回滚                        |
| 收藏与历史   | /api/me/favorites、/api/me/history            | 用户身份来自服务端会话                |
| 行为事件     | POST /api/events                              | 同意校验、批次限制、去重、脱敏        |
| 产品启动     | GET /go/:slug                                 | 服务端查允许目标、短时归因、302 跳转  |
| 产品回传     | POST /api/integrations/events                 | 签名验证、时间窗、幂等、重放防护      |
| 产品审核     | /api/admin/submissions                        | 最小权限、状态机和操作者记录          |
| 用户数据导出 | POST /api/me/export                           | 权限校验、异步导出、限时下载          |

### 2. 更改依赖注入入口

```ts
// 当前
export const repository: Repository = new IndexedDbRepository();

// 后续：需要先实现并验证 HttpRepository
export const repository: Repository = new HttpRepository("/api");
```

不要在各页面判断 `if (useBackend)`。登录身份由独立 AuthProvider 提供；删除客户端口令作为权限判断的逻辑。每个写接口必须在服务端重复校验授权。

### 3. 迁移已有数据

1. 在旧来源后台导出完整 JSON，并保留原始备份。
2. 服务端编写一次性导入程序，逐表验证 Schema。
3. 产品保留稳定 ID 和 Slug；重新生成敏感身份字段。
4. 排除 demo=true 的测试产品或导入专用测试环境。
5. 不把本地用户直接视为已验证线上身份；通过明确授权关联。
6. 分离本地测试事件与生产分析事件，禁止混算。
7. 不把本地 adminPinHash 当作线上管理员密码；通过可信管理员初始化流程建立账户。
8. 图片 data URL 迁移到对象存储，替换成资源 URL。
9. 导入完成后核对产品数、状态、分类引用、合集顺序、推荐位、链接域名。
10. 在固定环境完成冒烟测试，再切换运行配置。

### 4. 接入独立产品

`launch_id` 只是归因标识，不是用户身份凭证。仅向明确接入的自有产品或合作产品传递短期、限定目标的启动信息。签名在服务端完成，密钥不能出现在浏览器。目标产品回传到达后再记录 arrival；核心动作和支付仅接受可信回传。统一登录与流量归因分别设计。

### 5. 真正的后台安全与稳定性

上线多人服务后补齐服务端 RBAC、会话、速率限制、CSRF、输入校验、不可篡改审计、任务队列、备份恢复、迁移和监控。按已选技术栈实施，而不是把前端界面隐藏当作访问控制。

## IndexedDB 升级约定

前台导航精简使用 `migration-quiet-navigation-v1` 标记执行一次：只关闭旧版默认入口（通过 ID 与路径共同匹配），保留原名称、顺序、其他站点设置及自定义导航，不删除任何页面或产品。后台仍可重新启用，后续刷新不会再次隐藏。新数据库的默认导航也处于关闭状态；没有启用的入口时，不渲染空导航或移动端菜单按钮。

校园方向扩展只增加分类记录，不改变对象仓库结构。使用 `records` 中的 `migration-campus-categories-v1` 标记执行一次，避免刷新后重新创建用户主动删除的空分类。旧版首页「分类 / 合集 / 工具箱」模块通过 `normalizeHomeModules` 在读取时合并为校园探索，原配置和旧版快照不被清除；发布新的首页编排时才保存新版模块列表。导入旧备份也遵守同一兼容逻辑。

增加表或索引时提高 `openDB` 的版本号，在 `upgrade` 回调按旧版本递增迁移。禁止为升级直接删库。新增字段提供默认值并保留兼容读取。备份文件版本独立于 IndexedDB 版本；未来调整备份格式时提供显式转换和中文错误提示。

## 本地验证

- 新增产品 → 发布 → 前台可搜索 → 刷新后仍存在。
- 修改链接 → 精确允许域名通过 → 跳转前确认 → 访问历史记录。
- 存储失败时不显示保存成功。
- 未允许分析时不记录事件。
- 无效 JSON 导入不能覆盖现有数据。
- 清除个人数据不删除产品库。
- 不同浏览器来源的数据相互独立。
