# NEXT 服务端与运营后台

## 结构与边界

- Node.js 22 + TypeScript + Express 5；PostgreSQL 17 独立数据库。
- `server/app.ts`：公开内容、反馈、匿名事件、登录、权限、管理员、内容 CRUD、宣传页及备份导入接口。
- `server/security.ts`：scrypt 密码摘要、随机会话令牌、令牌摘要入库、HttpOnly / SameSite=Strict Cookie、CSRF。
- `server/migrate.ts`：事务迁移、迁移互斥锁、首次内容初始化。现有内容不随代码发布重置。
- `server/cli.ts`：迁移、首位超级管理员初始化、忘记密码后的服务器重置。
- `src/storage/http.ts`：前台 Repository 的 HTTP 实现。个人资料、收藏、访问历史仍保留在 IndexedDB；运营内容存数据库。

管理员有两个真实角色：超级管理员可管理账号及导入导出内容；内容运营可维护产品、分类、合集、推荐位、首页文案、导航、宣传页、反馈等。所有权限在接口层检查，不依赖隐藏按钮。禁止删除当前账号、停用或降级最后一位启用的超级管理员。修改账号会撤销该账号全部会话。

登录有效期 8 小时。密码至少 14 位，最多 128 位；不提供公开注册或默认密码。密码和数据库连接串不能写入 VITE_ 变量。生产 Cookie 仅走 HTTPS。所有写请求必须匹配 APP_ORIGIN；管理写请求还要携带当前会话 CSRF 令牌。服务重启后登录限流计数会重置；多实例部署前应改为共享限流存储。

## 本机启动

安装 Node.js 22 和 Docker Desktop 后，在仓库目录执行：

```powershell
npm ci
npm run setup:dev
npm run db:migrate
npm run admin:create
npm run dev:api
# 另一个终端
npm run dev
```

`setup:dev` 首次生成被 Git 忽略的 `.env`（随机数据库密码、admin 账号和随机管理员密码），不覆盖已有文件。密码在本机 `.env` 的 `ADMIN_PASSWORD` 中查看，不输出到日志。后台地址为 `http://127.0.0.1:5173/admin`。初始化成功后可以从 `.env` 移除管理员初始化密码，改密通过后台用户管理或 `npm run admin:reset`。

开发库使用独立 Compose 项目 `next-development`，端口仅绑定 `127.0.0.1:54329`。如果已有 `.env`，自行补齐 `POSTGRES_PASSWORD` 等配置。不要运行 `docker compose down -v`，它会删除开发数据库卷。

## 运营使用

1. **用户与权限**：创建、编辑、停用、删除管理员，设置或重置密码。更改自己账号后需要重新登录。
2. **首页图文**：编辑介绍、求职区、校园区、反馈区标题，以及八张卡片的标题、说明和插画。配图支持现有优化漫画与站内 / HTTPS 图片地址，不接受脚本或任意 HTML；本版未做图片上传与对象存储。
3. **首页编排 / 导航管理**：调整模块显隐、顺序和站内导航入口。
4. **宣传页面**：创建独立的 `/p/slug` 页面，编辑封面、摘要、图文段落、顺序和行动按钮，预览、保存草稿、发布、下线、删除。新增页不会自动挤进首页，可自行在导航中添加 `/p/slug`。已发布页保存为草稿会立即下线。宣传页修改使用版本时间进行并发冲突检测。
5. **产品管理**：维护独立产品链接、分类、状态等。定时发布由服务器每分钟检查，不再要求某个浏览器一直打开。
6. **操作日志**：服务端在业务事务中生成，客户端不能伪造或删除。数据库维护人员依然具备数据库权限，不将其宣传为防篡改存证系统。

公开 API 不返回草稿、未发布宣传页、管理员或日志。首页仍保留现有优化图片、漫画布局和响应式适配，不用通用富文本替换设计。

## 数据迁移与统计

旧 IndexedDB 不会被清空，也不会自动把本机内容上传到线上。若需要迁移：先在旧本地模式导出完整 JSON，再由超级管理员在服务端后台的「站点设置」确认导入。导入按照 ID 合并同类内容，不删除服务器其他记录；会忽略个人资料、旧本地口令、分析事件、会话和旧审计。部署不自动迁移不同用户浏览器内的内容。

服务器内容导出不包含管理员、会话或事件，适合内容迁移；不是完整数据库灾备。完整备份用 `deploy/backup.sh`，恢复用 `deploy/restore.sh`。

匿名行为上报默认关闭，旧本机统计的同意不直接沿用。用户在隐私页重新同意后，上报页面、产品曝光、点击和搜索词，随机访客标识保存在本机；无需收集简历和面试内容。事件保留 90 天，报表最多读取最新 20000 条，超过该量会截断，界面有说明。它不能代表未同意用户或第三方产品内部转化。清除本机数据不删除已经上报的匿名记录，已提交反馈由运营人员处理。

## 数据库设计与后续迁移

`admins` 存真实账号，`sessions` 存令牌摘要、CSRF 和到期时间。`documents` 使用 `(store,id)` 主键及 JSONB 文档，复用前端 Zod 契约，适合当前内容类型；产品、合集、宣传页各自有唯一 slug 索引。`schema_migrations` 记录迁移版本。内容写入和日志同事务，批量中任一字段不合法会整体回滚。

当前第 1 版为幂等建表。未来新增 schema 版本应按 `schema_migrations` 的版本号追加事务，不修改已应用迁移的语义。尽量使用先增后删的兼容迁移，让旧 API 可短期回退；破坏性迁移需先备份并单独维护。

## 验证

```powershell
npm test
npm run build
npm run build:server
docker compose --env-file .env -f deploy/compose.dev.yml exec -T db createdb -U next next_test
npm run test:server
npm run test:e2e
npm run test:e2e:server
```

测试库必须是 `next_test`，接口测试会清空该测试库 schema，请勿将生产数据库命名为 next_test 或向测试命令提供生产连接。浏览器服务端测试接续接口测试生成的账号，因此按上面的顺序运行。测试后端使用 3002，浏览器测试用 5180；纯前端回归用 5178，不占用本机开发站 5173。

生产部署见 `deploy/BACKEND.md`。
